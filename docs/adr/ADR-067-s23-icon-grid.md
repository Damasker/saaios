# ADR-067: S23 -- "Сейчас" переходит на сетку иконок, остальные страницы остаются списком

## Статус

Принято, 2026-09-13.

## Контекст

Ещё во время S13 (визуальный проход, ADR-057) пользователь явно
попросил "сетку/иконки как на телефоне", и было решено отложить это
отдельно ("Сейчас только шрифт + убрать «кнопки» у сводок, сетку
отдельно"). S23 -- этот отложенный пункт.

Из четырёх вкладок только "Сейчас" концептуально является app
launcher'ом -- ровно то, что на настоящем телефоне рисуется сеткой
иконок. "Входящие" (список задач/уведомлений), "Я" (список
настроек) и "Пространства" -- по своей природе текстовые списки, не
launcher'ы; превращать их в сетку иконок means изобретать иконки для
концепций, у которых иконки не имеют смысла (настройка яркости
экрана -- не "приложение"). Поэтому сеткой стала только "Сейчас".

## Решение

`render::draw_root` получил параметр `is_grid: bool` (передаётся
как `self.current_page == RootPage::Now`), переключающий, как
рисуется `content_actions`: обычным списком карточек (заголовок +
подпись + кнопка) или сеткой из квадратных "иконок" (3 колонки) с
подписью под каждой. `now_content_cards`/`now_action_at` перешли с
одноколоночного `stacked_row_rect` на новый `now_grid_rect` (3
колонки, та же 1080x2400-referenced-canvas арифметика) -- сам список
элементов (сначала установленные приложения, затем два `root.sui`
элемента) не изменился, изменилась только геометрия ячеек.

**Честно ограничено**: в проекте нет и не было пайплайна иконок
(нет ассетов, нет системы загрузки PNG/SVG на диск ни для одного
приложения). "Иконка" -- это цветной квадрат с первой буквой имени
приложения, тот же честный подход к плейсхолдерам, что уже
использовался для skeleton-строк загрузки. Настоящие иконки
приложений -- отдельный, более крупный незапланированный пункт
(нужен формат манифеста приложения для иконки, загрузка файла,
кеширование).

## Test

Host: `cargo test -p saai-shell` (28/28 ok, включая новый
`now_grid_rect_lays_out_three_columns_per_row`), `cargo clippy -p
saai-shell` чист (`draw_root` получил `#[allow(too_many_arguments)]`
-- восьмой параметр на давно устоявшейся чисто-данные функции, не
стоит городить структуру ради этого лишь одного лишнего аргумента).
Кросс-компиляция под `pixel7` профиль чиста.

Device: отложено (ADR-058). Ожидание при финальной проверке: сетка
из 3 колонок должна визуально отличаться от списка на остальных трёх
вкладках, тапы по ячейкам должны запускать то же самое приложение,
что и раньше (геометрия изменилась, логика "какое приложение на
каком индексе" -- нет).

## Последствия

- Настоящий пайплайн иконок приложений остаётся открытым пунктом --
  не запрашивался явно в исходной формулировке спринта ("сетка/
  иконки"), эта формулировка была прочитана как "сеточная раскладка
  с иконками-плейсхолдерами", а не как "интеграция с реальными
  ассетами приложений".
- `now_grid_rect`'s 3 колонки -- literal выбор, не завязанный на
  реальную плотность DPI устройства; при появлении реальных данных
  с устройства это может потребовать пересмотра (4 колонки на более
  широком экране и т.п.), уже честно заложено как "проверка
  отложена".
