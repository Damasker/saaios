# ADR-066: S20 -- Bluetooth сопряжение через уже built-но, но не подключённые bt-scan/bt-pair

## Статус

Принято, 2026-09-13.

## Контекст

Тот же урок, что и в S19 (ADR-065): предварительный обзор бэкенда
назвал Bluetooth "только сырые несвязанные HCI CLI-инструменты", и
на этот раз это оказалось в основном верно, но неполно. Перечитав
`native-init.c`'s `setup_bluetooth()` целиком, а не только сам факт
загрузки модулей: она загружает `bluetooth.ko`/`hci_uart.ko`,
создаёт нужные device-ноды и запускает только `/saaios/bt-init`
(прошивку контроллера) в фоне -- никакого `bluetoothd`, никакого
управляющего сокета вроде `wpa_supplicant`'s не поднимается.

Однако `build-native-c-image.sh` уже зашивает в образ три
полноценных инструмента поверх Bluetooth Management Socket (raw
`AF_BLUETOOTH`/`BTPROTO_HCI`, канал `HCI_CHANNEL_CONTROL`):
`/saaios/bt-scan` (обнаружение устройств, ~8с, пишет `DEVICE`/
`TRANSPORT`/`DONE` в stdout и сырые записи в `/run/bluetooth-
devices.bin`), `/saaios/bt-pair` (сопряжение по индексу из этого
файла, плюс `--status`/`--forget`/`--restore`, персистентность в
`/metadata/saaios/bluetooth.{devices,linkkeys}` через `MGMT_OP_PAIR_
DEVICE`) и `/saaios/bt-gatt-probe` (не использован в этом спринте).
Ни один из них никогда не упоминался ни в одном ADR и не вызывался
ни из `native-init.c`, ни из `saai-shell` -- полностью рабочий, но
никогда не подключённый код.

## Решение

Подключить `saai-shell` к этим уже существующим бинарям вместо
написания собственного HCI-кода:

- `bluetooth_trigger_scan()` -- `spawn()` (не блокирующий,
  detached) `/saaios/bt-scan`, stdout в `/run/saai-shell-bt-
  scan.log`.
- `bluetooth_scan_results()` -- парсит этот лог-файл заново при
  каждой перерисовке (без кеша, тот же принцип, что и
  `wifi_status_line`).
- `bluetooth_pair(index)` -- `spawn()` `/saaios/bt-pair <index>`,
  тоже detached, тоже в свой лог-файл.
- `bluetooth_pair_result()`/`bluetooth_status_summary()` -- читают
  этот второй лог-файл для отображения "Сопряжено: X" / "Ошибка
  сопряжения: Y", пока результат не появился -- статус остаётся
  "Идёт поиск..."/предыдущим.

**Почему `spawn()`, а не блокирующий вызов, как для большинства
других sysfs/`wpa_cli`-чтений в этом файле**: `bt-scan` сам по себе
блокируется на ~8 секунд, делая обнаружение; настоящее рукопожатие
сопряжения (`MGMT_OP_PAIR_DEVICE`) у `bt-pair` таймаутится 45
секундами и реалистично может занять заметное время, ожидая
подтверждения на другом устройстве. Блокировать `saai-shell`'s
собственный event loop на этот срок означало бы замораживание
всего сенсорного экрана на время сопряжения -- недопустимо для
touch-интерфейса. Обе команды запускаются detached с перенаправлением
stdout в файл; UI просто перечитывает файл при каждой перерисовке.

Новая карточка "Bluetooth" на "Я" (строка 10, после Wi-Fi) открывает
"Bluetooth устройства" -- тот же runtime-sized список, что и Wi-Fi
(`stacked_row_rect`), с рендерингом через обобщённый (S20)
`render::draw_row_list` (переименован из S19's Wi-Fi-специфичного
`draw_wifi_list` -- второе реальное использование той же формы
оправдывает обобщение параметром `title`, не более).

## Test

Host: `cargo test -p saai-shell` (27/27 ok, включая новый
`bluetooth_list_action_at_*`), `cargo clippy -p saai-shell` чист,
кросс-компиляция под `pixel7` профиль чиста.

Device: отложено (ADR-058). Ожидание при финальной проверке:
обнаружение устройств и сопряжение должны реально работать (это
существующие, ранее непроверенные в UI, но полные по функциональности
CLI-инструменты) -- в отличие от S19's пароля, здесь нет известного
структурного ограничения, блокирующего успех.

## Последствия

- `bt-gatt-probe` остаётся неподключённым -- вне зоны действия этого
  спринта (BLE GATT-инспекция не была частью исходного запроса
  "Bluetooth: сопряжение устройств").
- `bt-pair --restore` (восстановление ключей при загрузке) всё ещё
  не вызывается автоматически из `native-init.c` -- ранее сопряжённые
  устройства не переподключатся сами после перезагрузки без ручного
  запуска. Открытый пункт для будущей работы, не блокирующий этот
  спринт (сопряжение как таковое работает и без этого).
- Второй реальный урок в этой серии (после S19): обзор бэкенда,
  сделанный до старта серии (ADR-058), стоит перепроверять чтением
  исходников перед тем, как объявлять что-то "честным пробелом" --
  не всё, что выглядело отсутствующим, было отсутствующим.
