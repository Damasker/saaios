# ADR-091: HIA-04b Orb -- постоянные состояния, меню и негативный сценарий

## Статус

Принято, 2026-09-15.

## Контекст

ADR-090's спайк физически подтвердил, что Orb может рисоваться и
ловить тапы поверх существующего рендер-пайплайна `saai-shell`. Этот
ADR строит постоянную версию: `docs/os/sprints/HIA-ROADMAP.md`'s
HIA-04b просит реальный `Frame::Orb` с минимум тремя состояниями
(`IDLE`/`MENU`/`ATTENTION`, `LISTENING`/`CONTROL_LAYER` из документа-
источника отложены до Фазы 3), тап открывает меню, цвет берётся из
текущего пространства (HIA-02/03), и жёсткий негативный сценарий:
Orb никогда не перекрывает hit-test таб-бара/карточек.

## Решение

### Геометрия -- почему негативный сценарий гарантирован структурно,
не проверкой порядка

Каждая страница `Frame::Root` рисует свои карточки начиная с `y=430`
(2400-scale, тот же захардкоженный порог, что уже разделяют
`stacked_row_rect` и `now_grid_rect`). `orb_zone_rect(width, height,
menu_open)` жёстко ограничивает нижний край зоны Orb `y=410` --
двадцать пикселей запаса, ни при каком состоянии (включая открытое
меню). Когда меню открыто, зона растёт ВВЕРХ, в мёртвое пространство
заголовочного блока `draw_root` (`SURFACE`-залитый прямоугольник
`y=150..340`, у которого никогда не было своего hit-test), а не вниз,
в территорию карточек. Итог: карточки и таб-бар физически не могут
быть перекрыты Orb ни в одном состоянии -- это не проверяется
порядком веток в touch-диспетчере, это геометрическое свойство самих
прямоугольников (подтверждено тестом на трёх разных размерах экрана,
см. "Test").

Закрытое состояние -- зона ЕСТЬ квадратик (без spacer-трюка).
Открытое -- вертикальный `Node::linear` (`orb_view`, та же
`Node`/`layout()`-система, что `object_view`/`task_confirm_view`):
две строки действий сверху, сам квадратик снизу как кнопка закрытия.

### Состояния

```rust
enum OrbState { Idle, Menu, Attention }
fn orb_state(menu_open: bool, has_pending_notifications: bool) -> OrbState
```

Чистая функция без `Shell` -- `Menu` побеждает безусловно (осознанное
действие пользователя в процессе), иначе `Attention` отражает уже
живой сигнал (`inbox_notifications()`, S21/S30, теперь ещё и
провалившиеся задачи ADR-089), не искусственный флаг, придуманный
только ради этой фичи.

Цвет: `Attention` -- фиксированный тревожный красновато-оранжевый
(`rgb(230, 90, 70)`), намеренно НЕ одно из шести значений
`SpaceColor` (HIA-03), чтобы акцент пространства никогда не спутался
с "нужно внимание". `Idle`/`Menu` -- `space_color(...)` текущего
пространства -- буквально "цвет берётся из ContextFrame" через
HIA-03's уже существующую функцию.

### Меню

Два реальных действия, не заглушки: "Входящие" (`self.current_page =
RootPage::Inbox`) и "Новое намерение" (`self.intent_input =
Some(IntentInputState::default())`) -- та же навигация, что таб-бар и
карточка "Сейчас" уже используют, не новое поведение, придуманное для
этого меню. Полноценное контекстно-зависимое радиальное меню --
HIA-05, следующий пункт roadmap'а, не этот ADR.

### Rollback

`ShellSettings.orb_enabled: bool`, `true` по умолчанию, персистится
тем же ручным JSON-путём, что и остальные настройки. Новая карточка
"Orb" на "Я" переключает. Выключенный -- `orb_frame` в `draw()`
всегда `None` (квадратик не рисуется), и Orb-ветка touch-диспетчера
целиком пропускается -- таб-бар остаётся единственным путём
навигации в буквальном, не только визуальном смысле.

## Test

Host: `cargo test -p saai-shell` -- 74/74 (6 новых:
`orb_state_prefers_menu_over_attention`,
`orb_state_falls_back_from_attention_to_idle`,
`orb_zone_never_reaches_where_cards_start` -- прямая проверка
негативного сценария на трёх реальных размерах экрана (1080×2400,
800×480, 1440×3120), закрытое и открытое состояние оба,
`orb_action_at_toggles_the_closed_dot`,
`orb_action_at_misses_a_normal_card_row_when_closed` -- тап в точку
первой карточки не задевает Orb, `orb_action_at_finds_both_menu_
rows_and_the_close_dot_when_open`). `cargo clippy -p saai-shell
--all-targets` чист.

Device: подтверждено вживую без пересборки образа (`saai-shell`
живёт на `/data`, ADR-082), полный цикл:

1. Квадратик виден между заголовком и карточками на "Сейчас"
   (обычный бирюзовый -- `SpaceColor::Default`).
2. Тап открыл меню с двумя строками.
3. Тап "Входящие" закрыл меню и реально открыл "Входящие".
4. Негативный сценарий: тапы по вкладкам таб-бара и обычным
   карточкам сработали как обычно, несмотря на Orb наверху.
5. `Attention`: тестовое уведомление создано напрямую по протоколу
   `saai-entityd` (тот же throwaway-однострочный Rust-бинарь, что
   ADR-087/088, собран/запущен только для теста, не закоммичен) --
   квадратик сам покраснел без тапа. Оставался красным, пока хотя бы
   одно уведомление ждало (обнаружено на практике: несколько старых
   тестовых уведомлений с прошлых сессий тоже пришлось скрыть, прежде
   чем цвет вернулся -- ожидаемое поведение "Attention пока есть
   ХОТЬ ОДНО", не баг).
6. `Rollback`: тумблер "Orb" на "Я" выключил -- квадратик пропал на
   "Сейчас", таб-бар и карточки продолжили работать. Включён обратно
   после проверки.

## Последствия

- `docs/os/sprints/HIA-05` (radial menu) может начинать сразу с
  реальных `Frame::Orb`-состояний и уже существующего меню-каркаса
  (`orb_view`'s открытое состояние), не с нуля.
- `Listening`/`ControlLayer` (документ-источник, раздел 55) --
  сознательно не построены, ждут Фазы 3 (голос).
- Меню сейчас ровно два фиксированных действия -- не читает
  ContextFrame/открытый объект, это явно оставлено HIA-05.
