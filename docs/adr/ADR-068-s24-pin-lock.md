# ADR-068: S24 -- опциональный PIN на смену tap-to-unlock

## Статус

Принято, 2026-09-13.

## Контекст

С самого начала (S04, ADR-016 и далее) разблокировка была
одношаговой: любой тап-и-отпускание на lock-surface снимал
`SessionLock` безусловно. Это годилось для проверки самого факта
работы session-lock протокола, но не является защитой экрана
блокировки в каком-либо смысле. S24 -- запрошенный в изначальной
формулировке серии пункт "PIN/защита экрана блокировки".

## Решение

`ShellSettings.pin_code: Option<String>` -- `None` по умолчанию
сохраняет старое поведение (любой тап снимает блокировку) без
изменений для уже существующих файлов настроек на диске (обратная
совместимость: старый `shell-settings.json` не содержит этого поля,
парсится как `None`). Только явная установка PIN через "Я" →
"PIN-код" → "Изменить" включает защиту.

Новая цифровая клавиатура (`pin_keypad_rect`/`PIN_KEYPAD_DIGIT_
LABELS`) -- не переиспользование ADR-029's клавиатуры (там вообще
нет цифр). Используется в двух не пересекающихся по времени местах:
"Изменить PIN" на "Я" (обычный `Frame`-модал на toplevel-поверхности)
и сам lock-surface (`present_lock_pin_entry`, отдельный путь
рендеринга -- lock-surface никогда не использует общий `Frame`/
`draw()`, потому что toplevel скрыт под ней, ADR-016). Разблокировка
происходит автоматически, как только введено столько цифр, сколько в
PIN, и они совпадают; при несовпадении буфер очищается для повторного
ввода. На экране блокировки показываются только точки-индикаторы
прогресса (`ACCENT`/`MUTED`), сами цифры никогда не отображаются --
это то, что защита PIN-ом вообще означает.

**Честно ограничено**: PIN хранится в открытом виде в том же
`shell-settings.json`, что и остальные настройки -- не хуже, чем
`wpa_supplicant.conf`'s пароли Wi-Fi (S19) уже на том же диске, и
других локальных учётных записей на этом устройстве нет, так что
модель угроз не меняется. Нет пути восстановления забытого PIN,
кроме прямого редактирования/удаления файла настроек через serial
console -- приемлемо для одиночного hobby-устройства, не для
многопользовательского продукта.

## Test

Host: `cargo test -p saai-shell` (30/30 ok, включая два новых теста
для `pin_keypad_action_at`/`pin_setup_action_at`), `cargo clippy -p
saai-shell` чист, кросс-компиляция под `pixel7` профиль чиста.

Device: отложено (ADR-058). Это единственный спринт в серии,
трогающий путь разблокировки -- по умолчанию (`pin_code: None`)
поведение не должно отличаться от уже физически подтверждённого
tap-to-unlock ни на бит; PIN-путь (набор, ошибка, совпадение) нужно
проверить отдельно и в первую очередь при финальном проходе, именно
потому что ошибка здесь может физически заблокировать сенсорный
экран.

## Последствия

- Открытый пункт: удлинение/усложнение самого PIN (макс. длина,
  таймаут после N неверных попыток) не реализовано -- за пределами
  исходного запроса "PIN/защита", не блокирует закрытие спринта.
- Клавиатура (`PIN_KEYPAD_DIGIT_LABELS`) -- третий независимый набор
  клавиш в проекте после ADR-029's букв и S19's переиспользования тех
  же букв для Wi-Fi-пароля; троим экранам (Новое намерение, пароль
  Wi-Fi, PIN) теперь есть ровно два разных набора клавиш, не три --
  PIN использует новый цифровой, остальные два делят один буквенный.
