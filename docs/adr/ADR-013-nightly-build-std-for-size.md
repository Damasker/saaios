# ADR-013: Nightly `-Z build-std` для размера `saai-displayd`

## Статус

Принято, 2026-09-08.

## Контекст

S03 Change 6 подключает `saai-displayd` в `init_boot`-образ рядом с
`drm-splash` (fallback) и всем остальным уже упакованным в ramdisk
(`saaios-runtime`, `saaios-console`, `busybox`, `wpa_supplicant`, шрифты
и т.д.). `init_boot_a`/`init_boot_b` — партиции фиксированного размера
8388608 байт (8MB), подтверждено самим бутлоадером (`fastboot flash`
отказал: `not big enough`, партиция реально такого размера — не
предположение).

Собранный обычным способом (стабильный тулчейн 1.97.1, `[profile.pixel7]`:
`opt-level = "z"`, `lto = "fat"`, `codegen-units = 1`, `panic = "abort"`,
`strip = "symbols"` — уже максимально агрессивные настройки) `saai-displayd`
весит 1753512 байт. С ним итоговый образ — 8796544 байт, на 407936 байт
(~400KB) больше партиции. Первая попытка прошить была безопасно отклонена
бутлоадером — телефон не пострадал, ничего не записалось.

Проверенные варианты без выигрыша:
- дальнейшая настройка `[profile.pixel7]` — уже на максимуме;
- отключение неиспользуемой cargo-фичи `smithay/desktop` — экономия 48
  байт (LTO уже устраняет мёртвый код независимо от фичи);
- `--icf=all` (identical code folding на уровне линкера) — не
  поддерживается версией `lld`, встроенной в zig 0.13.0;
- урезание другого содержимого ramdisk (`wpa_cli`, `touch-monitor`) —
  оба активно вызываются из `native-init.c` в продакшене, не мёртвый вес.

## Решение

`saai-displayd` для Pixel 7 собирается через nightly Rust с
`-Z build-std=std,panic_abort -Z build-std-features=panic_immediate_abort`
(`os/targets/panther/build-saai-displayd.sh`, пин nightly —
`nightly-2025-06-01`; более новые nightly к 2026-09 требуют
дополнительный опт-ин `cargo-features = ["panic-immediate-abort"]` в
манифесте — это потребовало бы менять корневой `Cargo.toml`, что сломало
бы стабильную сборку всех остальных пакетов workspace'а тем же
манифестом; выбранный nightly ещё поддерживает старый, не требующий
изменений манифеста, синтаксис). Пересборка `std` без обычной
panic-unwinding/форматирования сообщений паники даёт нужные ~400KB:
итоговый бинарь — 1352848 байт (экономия 400664 байт, почти точно
устраняет overage).

Физически проверено на устройстве: бинарь, собранный этим путём,
инициализируется и рендерит идентично обычной сборке (hardware output,
touch input, Wayland-сокет, blit тестового паттерна — тот же sha256, тот
же результат на экране, подтверждено пользователем).

Это **не** влияет на остальной workspace: только это одно место сборки
использует nightly и `-Z`-флаги. Headless-тесты, CI's `test`-job,
`saaios-runtime`/`saaios-console` — всё остаётся на закреплённом
стабильном 1.97.1, `build-saai-displayd.sh` не трогает ни
`rustup default`, ни `[profile.pixel7]` в корневом `Cargo.toml`.

## Последствия

Положительные:

- `saai-displayd` помещается в фиксированную 8MB партицию вместе со всем
  остальным содержимым `init_boot`;
- ноль изменений для стабильного тулчейна где-либо ещё в репозитории.

Цена решения:

- бинарь для Pixel 7 (и только он) теряет сообщения паники и
  разворачивание стека при панике — `panic_immediate_abort` заменяет их
  прямым `abort()`. Не проблема для нормального пути (уже многократно
  физически проверен), но диагностика будущего краша на устройстве
  потребует пересборки без `-Z build-std`/`panic_immediate_abort`
  (обычным `cargo build --profile pixel7 ...` без этого скрипта) для
  получения текста паники — второй, менее сжатый бинарь для отладки, не
  для прошивки;
- зависимость от nightly-тулчейна для одного конкретного шага сборки —
  дополнительная установка (`rustup toolchain install`), 
  зафиксирован конкретной датой (`nightly-2025-06-01`), не "последний
  nightly", чтобы не наткнуться на будущие подобные breaking changes в
  экспериментальном API `-Z build-std`;
- если partition когда-нибудь всё равно понадобится больше 8MB (новая
  функциональность, новые бинарники) — этот запас конечен, придётся
  либо ужимать что-то ещё, либо пересматривать сам ramdisk layout.
