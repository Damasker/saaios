# ADR-065: S19 -- Wi-Fi сканирование и подключение через существующий wpa_supplicant

## Статус

Принято, 2026-09-13.

## Контекст

Предварительный обзор бэкенда (проведённый до старта серии S14-S25,
см. ADR-058) назвал Wi-Fi "нет динамического управления", исходя из
того, что `saai-shell` никогда не вызывал ничего, кроме
`wifi_is_up()` (чтение `operstate` для иконки статус-бара, S13).
Перед тем как писать S19, `native-init.c` был перечитан целиком, и
вывод оказался неверным: `setup_wifi()` уже запускает при каждой
загрузке полноценный `wpa_supplicant` (`-Dnl80211 -iwlan0 -c
/saaios/wpa_supplicant.conf -C/run/wpa_supplicant`, с
`update_config=1`), плюс `wpa_cli -a /saaios/wifi-action.sh` как
слушатель событий. Управляющий сокет `/run/wpa_supplicant` живой на
каждом боевом устройстве уже сейчас -- просто ничто в UI никогда его
не спрашивало.

## Решение

Построить сканирование/подключение как реальный клиент этого уже
работающего `wpa_supplicant`, через отдельные (без сохранения
состояния) вызовы `wpa_cli`:

- `wifi_scan_results()` -- парсит `wpa_cli scan_results`.
- `wifi_trigger_scan()` -- `wpa_cli scan` (не блокирует, результат
  подтягивается следующим `scan_results`).
- `wifi_status_line()` -- парсит `wpa_cli status` (`wpa_state=
  COMPLETED` + непустой `ssid=`).
- `wifi_connect_open`/`wifi_connect_psk()` -- `add_network` /
  `set_network` (`ssid`, `psk` или `key_mgmt NONE`) /
  `enable_network` / `select_network` / `save_config` (персистентно,
  благодаря `update_config=1`).

UI: карточка "Wi-Fi" на "Я" (строка 9, после "Громкость") открывает
полноэкранный список "Wi-Fi сети" (`Frame::WifiList`, по образцу
`Frame::TaskConfirm` -- заголовок плюс список, строки runtime-sized
через `stacked_row_rect`, как "Входящие"/"Сейчас"). Тап по открытой
сети подключает сразу; тап по защищённой сети открывает экран ввода
пароля.

**Честно ограничено**: экран ввода пароля переиспользует
существующую ADR-029 клавиатуру (`intent_view()`) буквально, той же
структурой узлов -- она поддерживает только строчные латинские буквы
и пробел, ни цифр, ни символов, ни заглавных букв. Это делает ввод
реального пароля WPA2 практически невозможным (почти ни один
настоящий пароль не состоит только из строчных латинских букв).
Подключение к открытым сетям и весь конвейер
сканирования/статуса реальны и полезны уже сейчас; подключение к
защищённым сетям с настоящим паролем упирается в саму клавиатуру, а
не в код этого спринта -- решение не блокировать S19 на переделке
клавиатуры, а честно задокументировать эту границу.

## Test

Host: `cargo test -p saai-shell` (26/26 ok, включая два новых теста
для `wifi_list_action_at`), `cargo clippy -p saai-shell` чист (один
`unnecessary_sort_by` warning исправлен -- `sort_by_key` +
`Reverse`), кросс-компиляция под `pixel7` профиль чиста.

Device: отложено (ADR-058). Ожидание при финальной проверке:
сканирование/статус/подключение к открытой сети должны реально
работать (это боевая инфраструктура, не догадка); подключение к
защищённой сети с паролем, содержащим цифры/заглавные буквы/символы,
физически невозможно ввести этой клавиатурой -- это будет
зафиксировано как известное ограничение, а не как баг.

## Последствия

- Реальный прогресс по сравнению с S18: это первый спринт серии,
  где новая функциональность подключена к уже работающей боевой
  инфраструктуре, а не к честно недоказанному предположению.
- Открытый пункт для будущей работы: клавиатура (ADR-029) нуждается
  в цифровом/символьном режиме, чтобы подключение к защищённым сетям
  стало практически полезным, а не только демонстрацией конвейера.
- `wifi_scan_results()`/`wifi_status_line()` шеллятся к `wpa_cli` на
  каждый `draw()` пока список/статус видны -- приемлемо, поскольку
  (как и `storage_string()`/`boot_slot()` до этого) перерисовка
  происходит по событию, а не в цикле кадров.
