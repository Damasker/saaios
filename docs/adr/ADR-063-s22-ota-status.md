# ADR-063: S22 -- статус OTA на "Я", честно только для чтения

## Статус

Принято, 2026-09-13.

## Контекст

S12 реализовал и физически подтвердил полный OTA-путь
(подпись/скачивание/запись/health/rollback, ADR-044..048), но
целиком как отдельные CLI-инструменты (`saai-ota-stage/-write/
-health`) без демона или протокола -- никогда не вызывались из
`saai-shell` или любого UI.

## Решение

Показать то, что уже реально персистентно на диске: слот загрузки
(`androidboot.slot_suffix` из `/proc/bootconfig`/`/proc/cmdline`) и
счётчик попыток загрузки (`/data/saaios/system/boot-attempts`,
`saai-ota-health`'s собственный формат, S12). Никакого действия
"проверить обновления сейчас" не добавлено -- сознательно: это
требует (а) настройки URL сервера обновлений, которой не существует,
(б) вызова OTA-бинарей по пути, который S12 никогда не фиксировал
как стабильный (ручной CLI, не часть `native-init.c`). Строить
интерактивность поверх непроверенного предположения было бы менее
честно, чем показать только то, что уже точно работает.

## Test

Host: тесты/clippy/кросс-компиляция чисты (без новых тестов -- два
прямых `/proc`/`/data`-чтения того же вида, что `kernel_release`/
`hardware_model` уже покрывают структурно).

Device: отложено (ADR-058).

## Последствия

- "Проверить обновления" остаётся открытым пунктом для будущей
  работы -- нужен либо URL-setting + обёртка-демон над
  `saai-ota-stage`, либо явное решение зафиксировать путь бинарей и
  вызывать их напрямую из shell.
