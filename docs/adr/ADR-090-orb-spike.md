# ADR-090: HIA-04a Orb -- физически подтверждено поверх существующего рендер-пайплайна (спайк)

## Статус

Принято, 2026-09-15.

## Контекст

`docs/os/sprints/HIA-ROADMAP.md`'s HIA-04a: до того, как строить
постоянный `Frame::Orb` (HIA-04b) с состояниями/жестами, физически
подтвердить, что точка-манипулятор вообще МОЖЕТ рисоваться и ловить
тапы поверх уже существующего UI (таб-бар + карточки), не заменяя
его -- та же throwaway-спайк методология, что ADR-029 уже
использовала для клавиатуры, до любого постоянного кода.

## Находка

Throwaway-патч к `services/saai-shell/src/main.rs` (НЕ закоммичен,
`git checkout --` отменил сразу после физической проверки):

- `orb_spike_rect(width, height) -> Rect` -- фиксированная позиция
  (140×140 или меньше на мелком экране, справа, `y=300`), та же
  форма, что любая другая вычисляемая геометрия в этом файле
  (`stacked_row_rect` и т.п.).
- `orb_spike_hit(pos, width, height) -> bool` -- `orb_spike_rect(...)
  .contains(pos.0, pos.1)`, переиспользует уже существующий
  `Rect::contains()` (`saai-ui-core`), а не новую хит-тест систему.
- В конце `draw()`, после отрисовки обычного `Frame` и до
  `apply_contrast_boost`: `render::Canvas::new(canvas, width,
  height).fill_rect(orb_spike_rect(width, height), render::ACCENT)`
  -- один квадратик, безусловно поверх всего, что нарисовал `Frame`
  этого кадра.
- В `TouchHandler::up()`, первая проверка внутри `self.tab_touch_
  pending` (раньше `pending_consent`/`viewing_entity_id`/tab-bar/
  content -- специально поверх ВСЕГО для этого теста, не итоговая
  приоритетность): `println!("saai-shell: ORB SPIKE tapped, active
  tab: {:?}", self.current_page)`.

В отличие от ADR-029 (которая физически проверялась в изолированном
`unshare -m` namespace с `uinput`-инъекцией синтетических тапов,
поскольку боевой `saai-shell` тогда жил только на фиксированном,
дорого перепрошиваемом образе) -- здесь `saai-shell` уже живёт на
`/data` (ADR-082), поэтому спайк развёрнут ПРЯМО на боевой,
единственный работающий процесс тем же hot-swap-путём, что уже
проверенно использовался весь этот roadmap (build → `file-recv` push
→ `mv` → `kill` для рестарта под supervision), без нужды в
изоляции/synthetic-инъекции -- откат тем же путём тривиален и дёшев,
а физический тап выполнил реальный человек, не `uinput`.

Проверено вживую, три отдельных факта, все подтверждены
пользователем/логом:

1. Квадратик реально виден поверх обычного содержимого (карточки/
   таб-бар) на любой вкладке.
2. Тап по квадратику пойман -- лог показал `ORB SPIKE tapped, active
   tab: Now`, точное активное состояние `self.current_page` на
   момент тапа.
3. Тап по ДРУГОЙ вкладке таб-бара (не по квадратику) переключил
   страницу как обычно -- существующая навигация не сломана
   присутствием Orb поверх неё.

После проверки патч отменён: `git checkout -- services/saai-shell/
src/main.rs`.

## Решение

Orb физически подтверждён как реализуемый поверх существующего
`Node`/`layout()`/`fill_rect`-рендер-пайплайна `saai-shell` -- не
нужен новый Wayland-протокол, новая поверхность, новый слой
композитора. Постоянная версия (`Frame::Orb`, HIA-04b) строится тем
же способом: `Rect`-геометрия + `fill_rect` + приоритетная проверка
в touch-дispatch, только с реальными состояниями
(`IDLE`/`MENU`/`ATTENTION`) вместо одного безусловного квадратика и
без "поверх всего, включая модалки" -- HIA-04b's собственный
негативный сценарий ("Orb не перекрывает существующие hit-test зоны
таб-бара/карточек") требует более аккуратного места в приоритетной
цепочке, чем этот спайк, который нарочно упрощал это для скорости
теста.

## Последствия

- Спайк не оставил кода в репозитории -- воспроизводим по этому ADR,
  как и предполагала методология ADR-029.
- HIA-04b может начинаться сразу с постоянной архитектуры
  `Frame::Orb`, не тратя время на повторное доказательство базовой
  механики.
