# ADR-039: S10's last piece -- space-scoped memory physically verified end to end

## Статус

Принято, 2026-09-11.

## Контекст

ADR-038 решило: memory остаётся плоским JSONL Platform Track'а,
партиционированным `space_id`, переданным от `saai-taskd` через
`ToolContext`, без миграции в `saai-entity-store`. Этот ADR реализует
решение в коде и физически подтверждает изоляцию между реальными
пространствами на реальном устройстве.

## Реализация

- **`tool-registry`**: `ToolContext` получил `space_id: Option<String>`
  -- механическая правка всех 17 мест конструирования по рабочей
  области (`ai-runtime`, `tool-registry`, `system-tools`, `telemetry`,
  `memory-store`), везде `None`, кроме двух мест, которые реально
  знают пространство (см. ниже).
- **`memory-store`**: `MemoryFact` получил `space_id: Option<String>` и
  `origin_correlation_id: Option<Uuid>` ("происхождение" -- тот же
  `correlation_id`, что уже используется во всём остальном audit
  trail). `visible_to()` -- политика видимости: свой space + глобальные
  (`None`) факты; запрос без пространства (`console-tui`) видит всё,
  как и раньше. `recall`/`list_recent`/`forget`/`format_context` теперь
  принимают `space_id: Option<&str>`. 9 host-тестов, включая явную
  проверку изоляции между пространствами и нулевой регрессии для
  безпространственного вызова.
- **Wire**: `ClientRequest::Diagnose` получил `space_id:
  Option<String>` (`#[serde(default)]`); `saai-taskd`'s
  `runtime_bridge::diagnose()` теперь всегда передаёт свой `--space`.
  Прямые консольные memory-операции (`MemoryRecall`/`MemoryTail`/
  `MemoryForget`) пространство не несут -- явный, зафиксированный в
  ADR-038 пробел (у `console-tui` пока нет понятия пространства
  вообще), везде `None`, нулевая регрессия.
- **`ai-runtime`**: `space_id` протянут через
  `handle_user_text_in_session` -> `handle_user_text_inner` -> вызов
  `format_context()` (контекст в system prompt) и в `ToolContext` для
  ветки немедленного выполнения (`PolicyVerdict::Allow` посреди
  `diagnose()`). Путь `confirm()` (`PendingConfirmation`,
  `policy-engine`) пространство не несёт -- ни один сегодняшний
  memory-инструмент не требует подтверждения, отдельно
  задокументировано как явный, не блокирующий пробел (ADR-038).

Полный `cargo test --workspace` (44 saai-taskd + 9 memory-store + 12
diagnose-slow-system e2e + весь остальной workspace) зелёный;
`cargo fmt --all`/`cargo clippy --workspace --all-targets -- -D
warnings` чистые.

## Физическая проверка

Тот же реальный Pixel 7. `saaios-runtime` и `saai-taskd` -- новые
сборки с этим кодом, временно подставлены поверх боевых бинарников
(тот же паттерн, что ADR-032/034 уже использовали для `saai-shell` --
подмена, тест, побайтовое восстановление, а не перепрошивка: memory --
не изменение boot-critical пути, реальный `init_boot` остаётся
нетронутым содержимым ADR-035/037). Два независимых `saai-taskd`
подняты одновременно, `--space home` и `--space work`, оба против
одного `saaios-runtime`:

1. Intent в `home` ("Запомни факт с помощью memory.remember: ключ
   door_color, значение синий") -- модель сама вызвала
   `memory.remember`; в `memory.jsonl` факт лёг с `space_id: "home"`
   и реальным `origin_correlation_id`.
2. Intent в `work` ("Используй memory.recall с запросом door_color...")
   -- модель вызвала `memory.recall`, ничего не нашла: "Не могу найти
   информацию о двери в памяти" -- **изоляция подтверждена**, факт из
   `home` не утёк в `work`.
3. Тот же запрос в `home` -- модель нашла факт: "Я помню, что на
   двери установлен синий цвет" -- **положительный случай подтверждён**.
4. Intent в `home` ("Используй memory.forget...") -- модель вызвала
   `memory.forget`, в `memory.jsonl` появилась tombstone-запись
   (`deleted: true`) с тем же `space_id`/`origin_correlation_id`.

Все три вызова инструментов (`remember`/`recall`/`forget`) сделаны
реальной моделью (`qwen2.5:3b-instruct`) по собственному выбору из
свободного текста -- ни один не вызван напрямую в обход planner-моста.
Старые, существовавшие до этого изменения факты (`live.usb_ncm`,
`INIT_CODE_SHOWN`) физически подтверждены читаемыми без `space_id`
(поле отсутствует, не `null`) -- обратная совместимость, не
теоретическая.

`saaios-runtime` восстановлен к исходному бинарнику (хэш
`e7b10968...`, сверен побайтово) и перезапущен с теми же аргументами;
16 тестовых сущностей (по 8 на `home` и по 4 на `work`... фактически
12 в `home`, 4 в `work`) удалены с явным подтверждением пользователя;
4 не относящиеся к этому раунду сущности в `home` (от более раннего
теста, `echo`-kind) намеренно не тронуты -- не входили в область этой
уборки.

## Решение

S10 закрыт полностью: последний кусок (memory, привязанная к
пространству) реализован и физически подтверждён -- факт, вспомненный
в одном пространстве, не утекает в другое; безпространственный
(консольный) доступ работает без регрессии; "происхождение" фиксируется
через уже существующий `correlation_id`.

## Последствия

- S10 -- все четыре куска (Change 1/2/3 + memory) закрыты и физически
  подтверждены. Roadmap может перейти к S11.
- Прямые консольные memory-операции без пространства и
  `PendingConfirmation`'s пространство остаются явно
  задокументированными, не блокирующими пробелами (см. ADR-038) --
  не входят в S10, не предрешают следующий спринт.
