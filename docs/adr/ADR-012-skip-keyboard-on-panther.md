# ADR-012: Не подключать клавиатурную способность на Pixel 7

## Статус

Принято, 2026-09-08.

## Контекст

`seat.add_keyboard(XkbConfig::default(), ...)` компилирует дефолтный
RMLVO-keymap через `libxkbcommon`. На физическом Pixel 7 это падает с
`SIGTRAP` внутри `HandleAliasDef` (`keycodes.c:406`, NULL-разыменование
при разборе `evdev+aliases(qwerty)`) — воспроизведено и с "evdev", и с
"base" rulesets, задокументировано в commit `1d05260` как отложенная,
неблокирующая на тот момент проблема (вероятно неполный/несоответствующий
вручную перенесённый набор `xkb-data`, не полноценная сборка через
build-пайплайн).

Change 4/5 (реальный DRM/touch на устройстве) обходили это временными,
никогда не коммитившимися сборками с полностью убранной инициализацией
клавиатуры — рабочий обход для ручного тестирования, но не решение.

Для Change 6 (встраивание `saai-displayd` в `native-init.c`'s `ui_slot`
вместо `drm-splash`) это перестаёт быть "не блокирует": `native-init.c`
будет запускать настоящий закоммиченный бинарник (с клавиатурой), и он
падает на старте безусловно. Под supervision-механизмом ADR-009 это
означает respawn-crash-respawn до исчерпания бюджета — `saai-displayd`
физически не сможет удержать UI-слот ни разу.

Два варианта:

1. Починить xkb-data по-настоящему: кросс-компилировать
   `xkeyboard-config`, включить реальные данные в образ, проверить
   побайтово. Правильно с точки зрения полноты, но отдельная, большая
   по объёму задача, не связанная с тем, что реально ломает Change 6.
2. Не подключать клавиатурную способность на этой цели вообще.

У Pixel 7 нет физической клавиатуры. `drm-splash.c` — уже работающий в
проде UI — доказывает, что этой архитектуре never понадобилась
`wl_keyboard`/xkbcommon-трансляция keysym'ов вообще: его собственная
экранная клавиатура (`keyboard_touch_action` и соседние hit-test'ы в
`drm-splash.c`) реализована через прямой разбор касаний по координатам,
без какой-либо keymap-компиляции.

## Решение

`seat.add_keyboard(...)` вызывается только под
`#[cfg(not(feature = "panther-hardware"))]` — то есть остаётся в
headless (S02) сборке как есть (там используется настоящий,
корректно установленный `libxkbcommon-dev` хоста, и уже существующие
S02-тесты keyboard-focus/synthetic-inject не трогаются), но полностью
отсутствует в реальной pixel7-сборке. `State.keyboard` field,
`FilterResult`/`XkbConfig`/`Keycode` импорты и debug-only
`inject-key` stdin-триггер — всё под тем же cfg-гейтом. Место, где
раньше `keyboard.set_focus(...)` выставлял фокус вместе с
`focused_surface`, для panther-hardware сборки теперь просто выставляет
`focused_surface` без обращения к клавиатуре.

## Последствия

Положительные:

- Change 6 разблокирован без побочной, отдельной по объёму задачи;
- никакого поведенческого изменения для headless S02 сборки и её тестов;
- решение соответствует реальному железу устройства (нет клавиатуры —
  нет клавиатурной способности), а не обходит баг искусственно.

Цена решения:

- если когда-нибудь понадобится настоящий `wl_keyboard` на panther target
  (внешняя Bluetooth/USB-клавиатура, физический дебаг через неё) —
  xkb-data всё равно придётся чинить по-настоящему; сейчас это явно
  отложено, а не решено;
- экранная клавиатура для будущего `saai-shell` (S04) должна будет
  реализовываться так же, как в `drm-splash.c` — через touch-хиттесты
  напрямую в приложении, а не через Wayland `wl_keyboard` протокол.
