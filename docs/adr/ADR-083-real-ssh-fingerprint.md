# ADR-083: настоящий SHA256-отпечаток ключа на экране пейринга

## Статус

Принято, 2026-09-15.

## Контекст

ADR-074's экран согласия SSH-пейринга с самого начала показывал не
настоящий отпечаток, а обрезанный base64 самого ключа (`docs/os/
ideas.md`: "не настоящий SHA256... нет sha2 в зависимостях saai-
shell"). Человек, смотрящий на экран, не мог свериться ни с чем --
`ssh-keygen -l` на его собственной машине покажет совсем другую
строку для того же ключа.

## Решение

`key_fingerprint()` теперь реально хеширует: декодирует base64-часть
ключа в сырые байты (`base64` крейт, уже был в дереве зависимостей
транзитивно -- добавлен в `[workspace.dependencies]` явно), берёт от
них SHA256 (`sha2`, уже используется `saai-displayd` для хеширования
кадров -- не новая зависимость для проекта в целом), кодирует хеш
обратно в base64 без padding и добавляет префикс `SHA256:` -- ровно
тот формат, что `ssh-keygen -l -f <ключ>` уже печатает по умолчанию.
Смысл не в "красивой строке", а в том, чтобы человек на экране
телефона мог свериться с тем, что видит на экране своего клиента.

Провал разбора (не `<тип> <base64> [комментарий]`, не валидный
base64) -- честный откат на исходный текст ключа целиком, не паника
и не пустая строка -- экран, назначение которого "дать человеку
отказать", не должен сам ломаться на нестандартном вводе.

## Test

Host: `cargo test -p saai-shell` -- 42/42 (два теста на
`key_fingerprint`: один сверяет golden-значение, независимо
посчитанное Python'овским `hashlib` для того же ключа, не просто
передельным вычислением того же кода; второй -- честный откат на
нераспарсенный ввод). `cargo clippy` чист.

Device: подтверждено вживую без пересборки образа -- `saai-shell`
живёт на `/data` (ADR-082), бинарь просто подменён через `file-recv`/
SSH. Сгенерирован новый тестовый ключ (`ssh-keygen -t ed25519`),
запрошен реальный `ssh-keygen -l -E sha256` отпечаток
(`SHA256:y7S9TZuBsH4dMcJTs6urnY0HY0TLifVtoy0GNtYftgo`), отправлен
запрос на пейринг этим ключом -- экран показал побитово идентичную
строку.

## Последствия

- `docs/os/ideas.md`'s пункт про ненастоящий отпечаток закрыт.
- Первый практический пример пользы ADR-082 -- правка развёрнута и
  проверена вживую без единой перепрошивки, ровно то, ради чего
  тот переезд делался.
