# ADR-062: S21 -- обобщённые уведомления, "Входящие" показывает оба вида

## Статус

Принято, 2026-09-13.

## Контекст

Единственный размеченный `entity_type` был `saaios.task` (S09/ADR-
031/032) -- никакой обобщённой модели уведомлений не существовало.
"Входящие" (S13 Change 2) показывала только задачи.

## Решение

Новый `entity_type` -- `saaios.notification`, свойства `{body, kind,
dismissed}`. `inbox_rows()` объединяет задачи и недismissed-уведомления
в один список (задачи первыми -- более actionable, не сортировка по
времени); `InboxRowKind` различает их для рендера и hit-теста
(`inbox_row_at`, замена `inbox_task_at`). Тап по задаче открывает
модалку подтверждения (как раньше); тап по уведомлению -- пишет
`dismissed: true` через тот же full-replace `update_entity`, что
`confirm_pending_task` уже использует для задач -- протокол
`saai-entityd` не менялся вообще.

Первый (и пока единственный) продюсер -- низкий заряд батареи,
целиком на стороне клиента: `check_low_battery()` читает уже
существующий `read_battery()` (S13) каждую секунду вместе с
обновлением статус-бара, создаёт уведомление через порог 15% (не
во время зарядки), `low_battery_notified`-флаг не даёт спамить каждую
секунду и сбрасывается, когда заряд восстанавливается выше порога.

## Test

Host: `cargo test -p saai-shell` -- 24/24 (без новых тестов -- вся
новая логика тонкая обвязка вокруг уже протестированного
`update_entity`/`create_entity`-пути). `cargo clippy` чист,
кросс-компиляция чиста.

Device: отложено (ADR-058).

## Последствия

- Уведомления, как и задачи, привязаны к текущему выбранному
  пространству (`self.selected_space_id`) -- то же существующее
  ограничение, что уже было у задач с S09, не новая проблема.
