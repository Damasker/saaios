# ADR-084: экран "Доверенные клиенты" со списком и отзывом

## Статус

Принято, 2026-09-15.

## Контекст

ADR-074 построила SSH-пейринг, но единственный способ увидеть или
убрать уже одобренный ключ был вручную через serial console/SSH --
`docs/os/ideas.md` называла это открытым пунктом с самого начала:
"Нет экрана 'доверенные клиенты' со списком/отзывом -- `authorized_
keys` растёт, но убрать оттуда запись можно сейчас только вручную".

## Решение

Новая карточка "Доверенные клиенты" на "Я" (сразу после "Удалённый
доступ (SSH)", `ME_FIXED_CARD_COUNT` 15 -> 16), открывает экран того
же вида, что уже используют "Wi-Fi сети"/"Bluetooth устройства"
(`render::draw_row_list`, переиспользован как есть, без единой новой
строчки в `render.rs`). Как и Bluetooth-список, ничего не кэширует --
`trusted_clients()` читает и парсит `authorized_keys` заново на
каждый тап/кадр, та же причина: список должен оставаться верным сразу
после действия, которое сам этот же файл меняет (отзыв).

Тап по строке = немедленный отзыв (`revoke_trusted_client()`,
перечитывает файл, убирает строку по позиции, переписывает целиком)
-- без отдельного подтверждения, та же логика "минимум подтверждений"
(docs/os/PRODUCT-PRINCIPLES.md), что уже применяется к подключению
к Wi-Fi/Bluetooth-сопряжению: реальный риск здесь низкий (отзыв
обратим -- владелец физически держит телефон, может заново одобрить
пейринг), и уже одобренные `dropbear`-соединения этим действием не
прерываются, обрывается только БУДУЩАЯ аутентификация. Строка сама
называет действие ("Отозвать") явно, так что тап не выглядит
случайным.

Каждая строка показывает имя клиента (`authorized_keys`'s comment-
поле, тот же единственный источник правды, что `docs/os/ideas.md`
уже фиксировала) и обрезанный `SHA256`-отпечаток (`key_fingerprint()`,
ADR-083) -- не просто имя, поскольку два клиента могут называться
одинаково, а отпечаток -- нет.

## Test

Host: `cargo test -p saai-shell` -- 43/43 (новый
`trusted_client_action_at_finds_clients_then_back`, тот же стиль, что
`bluetooth_list_action_at`'s собственный тест). `cargo clippy` чист.

Device: подтверждено вживую без пересборки образа (`saai-shell`
живёт на `/data`, ADR-082) -- экран открыт с "Я", показал реальные 4
существующие записи `authorized_keys` (`test-client`, `home-server-
test` -- два разных имени с ОДНИМ и тем же ключом, `decline-test-
client`, `fast-attempt-5`) с корректными отпечатками. Тап по
`decline-test-client` -- запись реально исчезла из файла на диске
(проверено напрямую по SSH), оставшиеся три записи, включая
действующий ключ сессии (`fast-attempt-5`), не тронуты -- SSH-доступ
продолжил работать сразу после отзыва.

## Последствия

- `docs/os/ideas.md`'s пункт про экран доверенных клиентов закрыт.
- Тумблер "Удалённый доступ" по-прежнему не трогает уже одобренные
  ключи при выключении (см. ADR-074's "Последствия") -- этот ADR не
  меняет то поведение, только даёт отдельный, явный способ убрать
  конкретный ключ вручную, когда он больше не нужен.
