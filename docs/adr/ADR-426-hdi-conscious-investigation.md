# ADR-426: аппаратная лаборатория вызывается только намерением

## Статус

Принято, 2026-10-10. HDI-00 и HDI-01 живут в `crates/hdi-contract`.
HDI-02 — `crates/hdi-exec`. HDI-03, HDI-04, HDI-05 и HDI-07…HDI-16 —
`crates/hdi-campaign`. Пробы `pci_drivers`, `platform_nodes` и
`platform_drivers` добавлены в белый список v1.
Шлюз намерения живёт в `intent_gate` и не подключён к `native-init`.
Демона и образа нет.
Физический прогон на MacBookPro11,3 ещё не начат: диагностического снимка нет.

## Нумерация

После ADR-425 следующий свободный номер — **426**.

## Контекст

SaaiOS уже умеет превратить сознательный ввод в наблюдаемый процесс:
`saaios.intent` → Task → Action → Result (ADR-030, ADR-120). PolicyEngine
даёт Allow / AskUser / Deny (ADR-260). Worker не наследует сессию
владельца и действует по связанному конверту (ADR-276). Наблюдение
становится фактом только когда оно свежее и проверяемое (ADR-274).

Отдельный вопрос — может ли заменяемая нейромодель по нескольким
проходам собрать достоверную модель компьютера, найти неизвестный
компонент и предложить, как его инициализировать. Первый стенд —
лично принадлежащий MacBook Pro 11,3 под Debian 13, userspace, без
правки загрузчика, драйверов и ядра. Ожидаемый ценный исход может
быть отрицательным: Intel Iris Pro 5200 на этом шасси часто не
выводится прошивкой на шину PCI, и read-only сессия не обязана уметь
её включить.

Этот трек не является модемным. Ограничения AGENTS.md для CP, EFS, NV
и SIT остаются в силе и сюда не переносятся как предмет работы.

## Решение

Лаборатория аппаратного исследования (HDI) — userspace-кампания.
Она не входит в `native-init`, не вешается на udev и не стартует
от загрузки или от появления устройства.

### 1. Единственный вход

Кампанию создаёт только `saaios.intent` с
`semantic_action_id = investigate_hardware`.

Автор намерения один из двух:

- человек: Orb или явная команда (`source` = `orb`);
- сама ОС: заранее объявленное предусловие сработало и записало Intent
  (`source` = `worker`, обязателен `precondition_id`).

Сработавшее предусловие создаёт Intent. Пробы оно не выполняет.
Предусловия поставляются выключенными (`enabled = false`). Пока правило
выключено, ОС лабораторию не формулирует.

На Debian-стенде до интеграции с `saai-taskd` тот же контракт имитирует
явный файл намерения, переданный командой. Команда без этого файла
кампанию не начинает. Юнит systemd, автозапуск и хук на шину не
создаются.

Неизвестное действие для существующего резолвера остаётся
Unsupported. Подключение `investigate_hardware` — отдельный спринт
HDI-05, не побочный эффект этого ADR.

### 2. Роли не смешиваются

Один Intent порождает одну кампанию. Лимит первой версии:
не больше пяти проходов, не больше пяти исполненных проб, потолок
риска `read_only`.

| Роль | Делает | Не делает |
|---|---|---|
| Normalizer | Снимок → хранилище свидетельств и редактированный пакет | Не вызывает модель |
| Control | Детерминированные утверждения из PCI/USB/модулей | Не вызывает модель |
| Investigator | Читает только редактированный пакет, отдаёт `ProbeRequest` | Не исполняет команды и не видит запечатанный ключ |
| Executor | Сверяет запрос с белым списком и PolicyEngine, пишет журнал | Не принимает произвольную строку оболочки |
| Verifier | Подтверждает или опровергает утверждения по `evidence_id` и ключу | Не вызывает модель |
| Knowledge | Хранит подтверждённое, отрицательные рецепты и пробелы драйверов | Не загружает код в ядро |

Модель заменяема. Контракт пробы стабилен. Тесты ходят со скриптовым
исследователем. Облачная модель и локальная малая модель — не часть
первых спринтов. Облачный вызов, когда он появится, получает только
редактированный пакет.

### 3. Запрос пробы структурирован

Единственная форма просьбы исследователя:

```json
{
  "campaign_id": "uuid",
  "pass": 1,
  "device": "pci:0000:01:00.0",
  "hypothesis": "discrete GPU is bound",
  "requested_probe": "pci_slot",
  "arguments": { "slot": "0000:01:00.0" },
  "risk": "read_only"
}
```

`requested_probe` — имя из белого списка, не путь и не argv.
Аргументы проверяются схемой этой пробы. Символы оболочки, перевод
строки и выход из разрешённого префикса дают Deny и запись в журнал.
Deny не повторяется автоматически.

Белый список v1: `pci_id`, `pci_drivers`, `pci_tree`, `pci_slot`, `usb_brief`,
`usb_tree`, `modules`, `drm_class`, `pci_sysfs_list`,
`dmi_allowlist`, `platform_nodes`, `platform_drivers`, `kernel_warnings_redacted`, `sysfs_read`.

В v1 отсутствуют как операции: `modprobe`, `insmod`, `rmmod`,
`setpci`, запись в sysfs, NVRAM, `efibootmgr`, запись в debugfs,
`/dev/mem`, загрузка модуля, правка загрузчика.

`sysfs_read` принимает один путь под префиксом
`/sys/bus/pci/devices/`, `/sys/class/drm/` или
`/sys/class/dmi/id/` и только для имён DMI из списка:
`product_name`, `product_version`, `board_name`, `bios_version`,
`bios_date`, `sys_vendor`.

Имя пробы `apple_gmux` в белый список не добавляется. Иначе ответ
первого стенда зашит в каталог инструментов.

### 4. Утверждение сравнимо без второй модели

Свободный текст модели не участвует в счёте. Утверждение:

```json
{
  "kind": "device_absent",
  "subject": "pci:0000:00:02.0",
  "value": "8086:0d26",
  "evidence_ids": ["ev-pci"]
}
```

Виды v1: `device_present`, `device_absent`, `driver_bound`,
`driver_unbound`, `causal`, `insufficient_evidence`,
`negative_recipe`, `driver_gap`.

Два утверждения совпадают, если совпали `kind`, `subject` и `value`.
Discovery gain — подтверждённые утверждения исследователя, которых
нет в множестве control. Утверждение без `evidence_ids` в знание не
попадает. `causal` без свидетельства остаётся гипотезой и увеличивает
счётчик ложных или неподтверждённых, но не gain.

Запечатанный ключ стенда лежит отдельно от пакета модели. Сериализация
входа исследователя не содержит поле ключа. Это проверяет тест.

### 5. Редактирование входит в нормализатор

В пакет модели не попадают MAC, серийные номера DMI, UUID, USB
`iSerial`, серийные номера дисков. Сырой снимок остаётся локальным и
не является входом модели. `lsusb -v` и полный `dmesg` в первый пакет
не входят; подробный журнал — отдельная проба уже после редактирования.
Журнал кампании хранит имя пробы, вердикт и хеш свидетельства, не
тело секрета.

PIN, IMSI, ICCID, IMEI и калибровка радио в этот трек не пишутся.
Первый стенд их и не собирает.

### 6. Адаптация — другой Action

`negative_recipe` и `driver_gap` — записи знания. Предложение
недостающего драйвера законно. Загрузка непроверенного кода в ядро
операцией лаборатории не является.

Применение рецепта, если оно когда-либо появится, — отдельное
действие `adapt_hardware` с вердиктом AskUser и состоянием
`waiting_confirmation`. В v1 исполнителя этого действия нет.

### 7. Метрики

Считаются на одной кампании и на контрольной ветке тех же данных:

| Метрика | Определение v1 |
|---|---|
| Identification accuracy | Доля субъектов запечатанного ключа, у которых kind и value совпали |
| Evidence coverage | Доля утверждений исследователя с непустым `evidence_ids` |
| Discovery gain | Число подтверждённых утверждений, которых нет у control |
| False hypotheses | Число опровергнутых утверждений исследователя |
| Probe efficiency | Discovery gain / число исполненных проб; 0 при нуле проб |
| Transferability | Знание с пометкой машины A не становится фактом машины B |

Transferability в физическом смысле начинается со второго стенда.
До него её доказывает фикстура, а не второй ноутбук.

### 8. Где жить коду, когда он начнётся

Будущие крейты, не члены init и не зависимости модема:

- `crates/hdi-contract` — типы, схема, редактирование, метрики;
- `crates/hdi-exec` — исполнитель по корню фикстуры;
- `crates/hdi-campaign` — цикл, скриптовый исследователь, верификатор.

HDI-05 только тогда добавляет разбор `investigate_hardware` в
`intent-resolution` и исполнение в `saai-taskd`. `native-init` не
меняется. Образ panther не меняется.

### 9. Первый физический вопрос

HDI-06 исследует графику MacBookPro11,3 одной сознательной командой.
Ключ проверки хранится в
[HDI-SEALED-KEY-mbp113.md](../os/sprints/HDI-SEALED-KEY-mbp113.md)
и в запрос модели не копируется. Успех прогона — таблица метрик и
журнал, включая допустимый отрицательный рецепт. Успех не требует
появления Iris Pro в `lspci`.

## Что не делается

Нет обучения своей модели. Нет второго PolicyEngine. Нет демона HDI.
Нет автозапуска на Debian или в SaaiOS. Нет правки ядра, загрузчика,
NVRAM и модулей на стенде. Нет модемных команд. Нет прошивки Pixel.
Нет оценки свободного текста второй моделью. Нет инструмента,
названного в честь ожидаемого ответа.

## Последствия

Пока HDI-05 не принят, фраза «исследуй железо» в Orb не запускает
лабораторию: действие ещё не зарегистрировано. Это сохраняет текущий
резолвер.

ОС может сформулировать намерение только после HDI-05 и только из
включённого предусловия. Первое предусловие
`graphics_class_incomplete` остаётся выключенным, пока HDI-06 не
покажет, какое наблюдение вообще считать неполнотой.

## Откат

Удаление этих документов возвращает дерево к состоянию без трека HDI.
Кода, который они включали бы в загрузку, нет.
