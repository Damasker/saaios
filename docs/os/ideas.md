# Идеи (черновик, не план)

Свободные мысли, возникшие по ходу работы -- ничего отсюда не входит
в roadmap автоматически, только после явного согласия, что сработает
и стоит того.

- Мастер-тумблер "Удалённый доступ" в v1 гасит только новые
  спаривания (pairing), но НЕ отзывает уже одобренные ключи и НЕ
  останавливает сам Dropbear (он просто продолжает слушать порт,
  как любой обычный sshd, без непройденной аутентификации толку
  всё равно ноль). Это сознательное упрощение ради скорости, не
  недосмотр -- см. ADR по этой фиче. Но честно: ADB прячет порт
  вовсе, когда "Отладка по USB" выключена. Можно дотянуть позже:
  native-init.c проверяет файл-флаг и держит/убивает процесс
  dropbear динамически.
- Как только `saai-shell` сам переедет на `/data` (следующий заход,
  ещё не сделано) -- обновления `saai-shell`/`saai-displayd` можно
  будет катить тем же SSH/scp, без единой перепрошивки вообще.
  Тогда единственная причина трогать `fastboot flash` останется --
  сам `native-init.c`/kernel-модули/дровер.
- Список доверенных клиентов сейчас читается прямо из
  `authorized_keys` (comment-поле = имя клиента) -- `saai-shell` не
  хранит отдельную копию списка. Это нарочно (один источник
  правды, тот же принцип, что ADR-030's "no cross-runtime
  dependency"), но если формат когда-то станет сложнее (даты
  последнего входа, IP и т.п.) -- потребуется отдельный JSON рядом.
- Fingerprint ключа в UI сейчас -- не настоящий SHA256, а просто
  обрезанный base64 (нет `sha2` в зависимостях `saai-shell`). Если
  захочется полноценный отпечаток -- добавить `sha2` (уже
  используется в `saai-displayd`, не новая зависимость для проекта
  в целом).
