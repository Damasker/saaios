# Sprint 13 — завершение пользовательского интерфейса

## Паспорт

- Состояние: `Ready` (2026-09-13). Definition of Ready согласован с
  пользователем через прямое обсуждение (не отдельный spike) --
  scope ниже отражает то, что пользователь явно подтвердил после
  того, как физическая проверка ADR-051/052 выявила пустые
  placeholder-вкладки и полностью не оформленный статус-бар.
- Зависит от: S01-S12 (все `Done`). Change 2 использует entity store
  (S06) и `saaios.task`-модель (S09/S10, `saai-taskd`) как есть, без
  изменений в их протоколах. Change 3 и Change 4 используют
  `saai-appd`'s `List`/`Launch`/`Stop` (S05, S07) как есть. Ни один
  Change не меняет ни один backend-протокол -- весь спринт целиком в
  `saai-shell` (клиентский рендеринг) плюс чтение уже существующих
  `/sys` источников для статус-бара.
- Архитектурные решения: новых ADR не открывается заранее -- каждый
  Change получает свой ADR по факту физической проверки, как во всех
  предыдущих спринтах. Ничего в этом спринте не трогает
  boot-critical путь, `native-init.c` или OTA -- откат сводится к
  откату конкретного бинарника `saai-shell`.
- Рабочий fallback: текущий (до этого спринта) `saai-shell`, уже
  физически подтверждённый ADR-051/052 -- переключение вкладок и
  всё остальное продолжает работать, просто без нового содержимого.

## Goal

Интерфейс `saai-shell` перестаёт быть демонстрационным skeleton'ом
(пустые вкладки-заглушки, statusbar без содержимого, одна
захардкоженная demo-карточка) и становится пригодным для реального
повседневного использования: видно время/связь/заряд, видно
ожидающие внимания задачи, видно и можно запускать все установленные
приложения, видно сводку по устройству и разрешениям приложений --
всё на уже существующих backend-данных, физически проверено на
реальном Pixel 7.

## Current state

Проверенные факты (session 2026-09-12/13, во время физической
проверки ADR-051/052):

- `ui/root.sui`: `content_actions` определены только для `page=now`
  (3 карточки, одна из них -- захардкоженный `manage_app:
  org.saaios.demo-surface`) и `page=spaces` (4 захардкоженных
  пространства). Для `page=inbox` и `page=me` записей нет вообще --
  `content_cards` для них пуст, `render::draw_root` рисует только
  серые placeholder-строки (сделано намеренно ADR-016, "чтобы переход
  между вкладками был заметен даже без реального контента").
- Статус-бар (`LayerSurface`, namespace `"saai-shell-statusbar-test"`)
  красит себя одним сплошным `render::BACKGROUND` и ничего не рисует
  -- ни часов, ни каких-либо иконок. Название с суффиксом `-test`
  подтверждает: это никогда не было завершено, а не сознательный
  дизайн пустого статус-бара.
- `saai-appd`'s протокол уже поддерживает `List`/`Launch`/`Stop`/
  `Remove`/`DecideConsent` (крейт `saai-app-protocol`) -- `saai-shell`
  использует их только для одного захардкоженного `org.saaios.
  demo-surface`, не для реального списка установленных приложений.
  Точечного `revoke` одной capability у уже согласованного приложения
  в протоколе нет -- только `DecideConsent` (всё-или-ничего при
  установке/первом запуске) и `Remove` (полное удаление).
- `self.spaces`, `self.entity_counts`, `self.selected_entities` уже
  трекаются в `Shell` для нужд текущей вкладки "Пространства" --
  готовые данные, просто не показаны нигде за пределами неё.
- Реальные источники для статус-бара подтверждены командной строкой
  на устройстве: `/sys/class/power_supply/maxfg/capacity` (`37`),
  `.../status` (`Discharging`) для батареи; `/sys/class/net/wlan0/
  operstate` (`up`/`down`) для Wi-Fi. `wlan0` в момент проверки был
  `down` (не подключён ни к какой сети в тестовом окружении) --
  индикатор должен честно показывать реальное состояние, включая
  "нет сети", а не предполагать всегда включённый Wi-Fi.
- Ни движка тем, ни экрана переключения тем не существует -- один
  захардкоженный набор цветов в `render.rs` (`BACKGROUND`, `SURFACE`,
  `ACCENT`, `TEXT`, `MUTED`, и т.д. -- уже используются согласованно
  во всех текущих экранах).

## Scope

Входит:

- Change 1 -- статус-бар: часы (системное время), индикатор Wi-Fi
  (по `operstate`), индикатор батареи (проценты + состояние заряда по
  `maxfg`). Обновление периодическое (не событийное) -- как и текущий
  `refresh_apps_if_due()`, нет смысла в push-модели для этих данных.
- Change 2 -- вкладка "Входящие": реальный список `saaios.task`
  entities со статусом `waiting_confirmation` из `self.selected_
  entities` (уже трекается); тап по элементу открывает существующий
  task-confirm экран (переиспользует `pending_task_confirmation`/
  `confirm_pending_task`, расширяя выбор с "первой найденной" на
  "выбранной пользователем из списка"). Пустой список -- честный
  "нет ожидающих задач", не серые placeholder-блоки.
- Change 3 -- вкладка "Я": сводка устройства из уже трекаемых данных
  (пространства, счётчики entity) + список установленных приложений
  с их текущими `granted_capabilities` (только чтение -- см. Current
  state про отсутствие точечного revoke в протоколе).
- Change 4 -- вкладка "Сейчас": единственная захардкоженная
  demo-карточка заменяется на настоящий динамический список всех
  установленных приложений (`saai-appd`'s `List`), каждое реально
  запускается через уже существующий `manage_app:<app_id>` путь.
- Change 5 -- визуальный проход: единая, согласованная, отполированная
  палитра/отступы/типографика по всем экранам (включая новые из
  Change 1-4) -- один вид, не переключаемая тема.

Не входит:

- Переключение тем (светлая/тёмная и т.д.) -- отдельный будущий
  спринт, если понадобится.
- Точечный revoke одной capability у уже согласованного приложения --
  протокол `saai-app-protocol` не поддерживает, добавление нового
  wire-message -- вне объёма этого спринта.
- Push-уведомления / real-time badge на вкладке "Входящие" --
  периодического опроса (как у существующего `refresh_apps_if_due`)
  достаточно для Definition of Ready.
- Любые изменения в `saai-appd`, `saai-taskd`, `saai-entityd` или
  entity store -- весь спринт использует их протоколы как есть.
- Экран настроек системного уровня (Wi-Fi pairing, звук, экран) --
  не входит ни в один Change; "Я" ограничен сводкой устройства и
  приложений.

## Change

1. Статус-бар: часы + Wi-Fi + батарея (наименьший риск, ни один
   существующий экран не трогается, чисто аддитивно).
2. Вкладка "Входящие": список задач из уже трекаемых данных.
3. Вкладка "Я": сводка устройства + список приложений с грантами.
4. Вкладка "Сейчас": реальный список приложений вместо захардкоженной
   demo-карточки.
5. Визуальный проход по всем экранам (после того как весь новый
   контент существует, чтобы полировать финальный набор, а не
   промежуточный).

## Test

- unit: новые чистые функции форматирования (время, проценты батареи,
  список задач/приложений в `ActionCardView`) -- table-driven тесты
  по образцу существующих (`selected_indicator_moves_between_edge_
  tabs` и др.).
- host integration: существующий `cargo test -p saai-shell` остаётся
  зелёным на каждом Change; `cargo clippy -p saai-shell` чист.
- device/physical: каждый Change развёрнут через уже установленный
  `cp && mv` + `chmod` паттерн (ADR-042) и физически проверен на
  реальном экране перед переходом к следующему -- то же дисциплина,
  что для ADR-051/052 в этой же сессии.

## Acceptance criteria

- Статус-бар показывает реальное текущее время устройства, реальное
  состояние `wlan0` (не всегда "подключено") и реальный процент
  батареи с `maxfg`, физически подтверждено сверкой с показаниями
  `date`/`cat .../capacity` на устройстве в момент проверки.
- "Входящие" показывает ноль или больше настоящих задач из entity
  store, физически подтверждено созданием тестовой задачи через
  существующий intent-flow и наблюдением её в списке; пустой список
  показывает честный текст, не placeholder-блоки.
- "Я" показывает настоящее число пространств/entity и настоящий
  список установленных приложений с их текущими грантами, сверено
  с прямым запросом к `saai-appd`/entity store по serial-консоли.
- "Сейчас" показывает все установленные приложения (не только demo),
  каждое реально запускается тапом.
- Ни один существующий физически проверенный сценарий (lock/unlock,
  deep idle/псевдо-сон ADR-051, производительность переключения
  ADR-052, consent screen, intent input) не регрессирует -- каждый
  спот-проверяется после Change 5.

## Threat / privacy impact

Новых данных, полномочий или каналов не вводится -- всё, что
показывается, уже читалось/хранилось (entity store, appd, `/sys`
только на чтение). Список грантов приложений на "Я" -- это уже
существующая, уже вычисляемая на сервере информация
(`granted_capabilities`), просто впервые показанная пользователю;
это снижает, а не повышает риск (пользователь теперь ВИДИТ, что уже
разрешено, вместо того чтобы не знать).

## Rollback

Для каждого Change -- предыдущий физически подтверждённый бинарник
`saai-shell` (тот же `cp && mv` откат, что использовался весь этот
проект). Ни один Change не трогает `saai-displayd`, `saai-appd`,
`saai-taskd`, `saai-entityd`, партиции или boot-путь -- откат
целиком в пределах одного пользовательского процесса.

## Evidence

Заполняется по каждому Change при физическом подтверждении (см.
паттерн ADR-044..052).
