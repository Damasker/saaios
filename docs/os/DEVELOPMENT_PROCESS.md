# Процесс разработки SaaiOS

## Источник истины

- [дорожная карта](sprints/README.md) определяет порядок и состояние спринтов;
- ADR фиксируют решения, которые дорого отменять;
- target-документы фиксируют только проверенные аппаратные факты;
- код и автоматические тесты являются исполняемой спецификацией;
- журнал спринта связывает цель, изменения, доказательства и rollback.

Нельзя отмечать аппаратную функцию готовой только по успешной сборке или
эмуляции.

## Ритм

Спринт — один проверяемый вертикальный результат длительностью не более двух
недель. Если результат не помещается, он делится до начала реализации. В любой
момент активен один аппаратно изменяющий эксперимент; документация, host-тесты
и независимые сервисы могут выполняться параллельно.

Состояния работы:

```text
Backlog -> Ready -> In progress -> Verify -> Done
                     |                |
                     └-> Blocked <----┘
```

`Blocked` всегда содержит наблюдаемый факт, уже проверенные гипотезы и условие
разблокировки. Неопределённость сама по себе не является блокером.

## Definition of Ready

Задача входит в спринт, когда у неё есть:

- одна цель и наблюдаемая ценность;
- исходное состояние и зависимости;
- ограниченная область кода/устройства;
- критерии приёмки, включая негативный сценарий;
- способ тестирования без телефона, если это возможно;
- безопасный rollback и известный рабочий артефакт;
- оценённые риски для данных, загрузки, безопасности и энергии;
- ADR или явная пометка, что нового архитектурного решения нет.

## Definition of Done

Задача или спринт завершены только когда:

- критерии приёмки выполнены, а результат записан;
- форматирование, lint, unit и integration tests зелёные;
- целевой AArch64 artifact собирается воспроизводимо;
- пройден подходящий device smoke test;
- для визуального/аппаратного изменения получено физическое подтверждение;
- проверены падение, перезапуск и rollback затронутого компонента;
- новые API, manifest/schema и ограничения документированы;
- документация не обещает ещё не реализованную безопасность;
- секреты и состояние телефона отсутствуют в diff и архиве;
- commit содержит одну законченную идею и сразу отправлен во все рабочие
  remotes после зелёной проверки;
- индекс спринтов и target status обновлены.

## Обязательная запись каждого изменения

Используется существующая форма инженерного трека:

```text
Goal
Current state
Change
Test
Acceptance criteria
Rollback
```

Дополнительно для UI/app-platform указываются:

```text
Threat / privacy impact
Telemetry without user content
Real-device evidence
Known limitations
```

## Классы проверки

| Уровень | Что доказывает | Обязателен когда |
|---|---|---|
| Unit | локальная логика и крайние значения | всегда для новой логики |
| Protocol/schema | совместимость сообщений и manifest | меняется граница процесса |
| Host integration | два настоящих процесса проходят сценарий | сервис или Wayland-клиент |
| Fault injection | компонент падает без потери управления | lifecycle, shell, compositor |
| Image inspection | состав, размер, хеши, отсутствие секретов | меняется образ |
| Device smoke | загрузка, экран, touch, USB recovery | меняется phone artifact |
| Physical acceptance | цвет, жест, звук, вибрация, power | человеко-аппаратное свойство |
| Cold reboot | постоянство и порядок старта | сохраняется состояние |

Подробная матрица находится в [QUALITY.md](QUALITY.md).

## Git и артефакты

- маленькие тематические commits, без смешивания чужих изменений;
- успешный commit пушится сразу, а не накапливается локально;
- бинарные firmware, credentials и per-device state не коммитятся;
- каждый установленный образ имеет SHA-256 и ссылку на исходный commit;
- стабильный пользовательский архив создаётся только из физически принятого
  образа;
- возвращаемый образ не перезаписывается до подтверждения нового.

## Изменение планов

Порядок спринтов можно менять после появления новых данных, но изменение
фиксируется в roadmap с причиной. Решение, затрагивающее системные границы,
протокол безопасности, формат данных или rollback, требует нового ADR.
